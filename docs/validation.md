## 自動實際操作

- 1920／1440／768／390／320px 首頁無水平溢位，播放列開啟時也測 1440／768／390／320px。
- 五支 MP4：播放時間前進，定位到片中且時間確實到達目標 ±3 秒，關閉卸載與焦點恢復。
- 41 首 MP3：每個版本在新播放列時間前進、關閉清除來源；沒有完整聽完所有作品。
- 影集 17／2 集選擇與下一集、第五集深連結、直接音樂深連結不自動發聲；第三方連線在這組測試隔離，不能由此聲稱 YouTube 串流通過。
- 佇列建立、前／下一首、換分類不換佇列；定位近片尾後由**真正 ended** 接續下一首，關閉接續後停在原曲。非派發假 ended 事件。

- 剪貼簿拒絕時，完整作品／網站網址可選取複製。無 JS 首頁仍有 7 組卡、7 首預設歌曲，完整目錄有 19 集＋41 首音樂。
- JSON 503 保留靜態內容；MP4／MP3 404 顯示文字與直連備援；減少動態、無頁面 JS 例外。

## 測試中修正的問題

最初用 Python 簡易 HTTP 伺服器測片尾，未緩衝位置的 seek 回到開頭；檢查發現其沒有 byte-range 支援，音檔已緩衝到約 145 秒但定位目標是 166 秒。因此補 `scripts/serve.mjs`，以 206 / Content-Range 真正提供指定 bytes。有效 100–199 範圍回 100 bytes、無效範圍 416、`.git/config` 404。改用它後，實際片尾接續測試通過。

舊版只驗「不在 seeking、readyState 足夠」，不足以證明跳到指定時間；本輪影片驗證增加目標時間差，避免把跳回開頭誤判成定位成功。公開服務仍需獨立確認 Range 行為。
